# Hatch

`hatch` 명령은 클릭한 점을 둘러싼 영역을 패턴으로 채웁니다. 경계는 먼저 그려지지 않습니다 — 캔버스에 이미 그려진 것으로부터 결정되므로, 끝과 끝이 만나는 네 개의 개별 [Line](../line/)은 닫힌 [Polyline](../polyline/)이 그러는 것과 정확히 같은 방식으로 영역을 둘러싸며, 내부에 있는 닫힌 도형은 채우기가 건드리지 않는 섬이 됩니다.

## 영역 채우기

1. 터미널에 `hatch`를 입력하거나 툴바의 **Hatch** 버튼(스와치 아이콘)을 클릭하세요.
2. 채우고 싶은 영역 안의 **점을 클릭**하세요.
3. 명령은 활성 상태로 유지되므로, 계속 클릭하여 더 많은 영역을 채울 수 있습니다 — 각 클릭은 자체 `Hatch` 객체를 생성합니다.
4. 완료되면 **Enter**, **Space**, 또는 **Escape**를 누르세요.

```
  ┌─────────────┐        ┌─────────────┐
  │             │        │▓▓▓▓▓▓▓▓▓▓▓▓▓│
  │   ○         │  --->  │▓▓▓( )▓▓▓▓▓▓▓│   바깥쪽 경계 안을
  │             │        │▓▓▓▓▓▓▓▓▓▓▓▓▓│   클릭; 원은 섬으로
  └─────────────┘        └─────────────┘   남음
```

## 키보드 참고

| 키 | 동작 |
|-----|--------|
| `Enter` / `Space` | Hatch 명령 종료 |
| `Escape` | Hatch 명령 종료 (Enter/Space와 동일) |

## 경계를 형성할 수 있는 것

다음 객체 유형의 어떤 조합이든, 간격 없이 끝과 끝이 연결되어 있는 한 어떤 조합으로든 경계를 형성할 수 있습니다:

- [Line](../line/)
- [Arc](../arc/)
- [Circle](../circle/) (자체 닫힌 경계)
- [Ellipse](../ellipse/) (닫힌 것, 또는 더 큰 루프의 일부로서 열린 타원호)
- [Polyline](../polyline/) (열림 또는 닫힘) 및 [Rectangle](../rectangle/)
- [Spline CV / Spline Fit](../spline-cv/)

Text, Multileader, Dimension 객체는 절대 경계로 취급되지 않습니다.

## 섬

클릭한 영역 안에서 완전히 닫혀 있는 모든 것 — 원, 닫힌 폴리선, 다른 hatch의 경계 — 은 **섬**이 됩니다: 채우기는 그 가장자리에서 멈추고 섬 자체는 비어 있는 채로 남습니다. 닫힌 도형을 다른 닫힌 도형 안에 넣으면 채우기가 번갈아 나타나며, 각 레벨에서 동일한 내부/외부 규칙을 따라 구멍 안의 채우기 안의 구멍이 됩니다.

## 클릭이 실패했을 때

클릭한 점이 둘러싸여 있지 않거나 경계에 틈이 있으면, 터미널은 조용히 아무것도 하지 않는 대신 이유를 설명합니다:

| 메시지 | 의미 |
|--------|------|
| "no boundary found" | 클릭한 점에서 어느 방향으로도 아무것도 감지되지 않았습니다 — 근처에 경계가 전혀 없습니다 |
| "point is not enclosed" | 근처에 경계가 있지만, 그것이 형성하는 도형에 클릭한 점이 포함되지 않습니다 |
| "boundary is open" | 가장 가까운 경계 어딘가에 틈이 있습니다 — 이를 추적하여 모든 접합부가 정확한지 확인하세요 |
| "boundary too complex" | 순회 한도 내에서 경계 루프를 닫을 수 없었습니다 — 일반적으로 겹치는 객체의 얽힘입니다 |

클릭이 실패한 후에도 명령은 활성 상태로 유지됩니다 — 메시지를 읽고, 도면을 수정하거나 다른 곳을 클릭한 후 다시 시도하세요.

## 패턴 선택

모든 새 hatch는 `ANSI31`로 채워진 상태로 시작합니다(또는 *마지막*으로 편집한 hatch가 사용한 패턴) — 그리기 전에는 패턴 선택기가 없습니다. 다른 패턴을 사용하려면:

1. 기존 hatch를 선택하고 속성 패널에서 **Pattern** 필드를 여세요 — 이렇게 하면 패턴 선택기가 열리며, 각 패턴이 어디서 왔는지에 따라 그룹화된 이름이 있는 스와치 그리드가 표시됩니다.
2. 패턴을 클릭하여 적용하세요 — 채우기가 즉시 업데이트됩니다.

이 선택은 `hatch` 명령으로 만드는 *다음* hatch의 기본값도 됩니다. 레이어나 색상을 선택하면 이후로 전달되는 것과 같은 방식입니다. 따라서 특정 패턴으로 여러 새 영역을 hatch하려면: 한 영역을 채우고, 그 패턴을 한 번 설정한 다음, 계속 hatch하세요 — 이후의 모든 채우기는 이미 해당 패턴이 적용된 상태로 시작됩니다.

자체 `.pat` 패턴 파일을 업로드하고 전체 라이브러리를 찾아보려면 [Hatch Manager](../hatch-manager/)를 참조하세요.

**SOLID**는 패턴 목록의 일반 항목이며, 별도의 체크박스나 모드가 아닙니다 — ANSI31이나 다른 이름이 있는 패턴을 선택하는 것과 같은 방식으로 선택하세요.

## 속성

| 속성 | 의미 |
|------|------|
| Pattern | 공유 패턴 어휘의 패턴 이름 ([Hatch Manager](../hatch-manager/) 참조) |
| Pattern Scale | 패턴 선의 간격을 조정합니다 — 값이 클수록 패턴 선이 더 멀리 떨어집니다 |
| Pattern Angle | 경계와 독립적으로 패턴을 회전시킵니다 |
| Origin X / Origin Y | 도면 좌표에서 패턴 자체의 반복이 고정된 위치 |

hatch를 이동, 회전, 대칭, 또는 크기 조정하면 패턴 배치도 함께 이동하므로 채우기가 경계와 정렬된 상태를 유지합니다 — 변환 후 스케일이나 각도를 다시 설정할 필요가 없습니다.

## 경계의 그립 편집

선택된 hatch는 Polyline이 정점을 잡는 것과 같은 방식으로 경계를 잡습니다 — 두 변이 만나는 모든 모서리에 그립이 하나씩 있고, 각 변의 중간에 하나씩 있습니다(원이나 타원의 hatch 같은 닫힌 루프는 대신 네 개의 축 점에서 잡습니다).

| 그립 | 동작 |
|------|------|
| **모서리** | 해당 모서리를 이동합니다. 직선 변은 정확히 따라갑니다; 호는 양쪽 이웃을 계속 통과하도록 다시 맞춰집니다; 타원이나 스플라인 변은 자체 곡선 위 어딘가에만 착지할 수 있으므로 모서리는 그 위의 가장 가까운 점에 달라붙습니다 |
| **변 중간 — 선, 타원, 또는 스플라인 변** | 변 전체를 슬라이드시킵니다; 양쪽의 변은 계속 연결된 상태를 유지하도록 잘리거나 연장됩니다 |
| **변 중간 — 호 변** | 슬라이드시키는 대신 커서를 통해 호를 **휘게** 합니다 — 양쪽 끝은 정확히 원래 위치에 그대로 있고, 경계의 다른 어떤 것도 움직이지 않습니다 |
| **중심** (전체 hatch) | 전체 hatch에 대해 [Move](../move/)를 활성화합니다 |

드래그하는 동안 드래그 미리보기는 채워진 실선 대신 점선 윤곽으로 경계를 표시합니다 — 미리보기는 이미 있는 것 위에만 그릴 수 있고 그것에서 무언가를 제거할 수는 없기 때문에, 원본 채우기는 놓을 때까지 아래에 계속 보입니다.

## DXF — HATCH 객체

Hatch는 `HATCH` 객체에서 **가져오기**됩니다: KulmanLab은 경계 지오메트리와 함께 패턴 이름, 스케일, 각도(DXF 그룹 코드 70/41/52)를 읽습니다 — 파일에 인라인으로 작성된 패턴 자체의 선 정의는 **읽지 않습니다**. 대신, 패턴 이름은 KulmanLab 자체 패턴 라이브러리(내장 기본값 및 [Hatch Manager](../hatch-manager/)에 업로드한 모든 것)에서 조회됩니다. 라이브러리에 없는 이름은 ANSI31로 대체되어 도면이 여전히 hatch된 것으로 읽히며, 참고 사항이 한 번 기록됩니다.

다른 애플리케이션이 작성한 스플라인으로 경계가 지정된 루프(DXF 경계 에지 유형 4)는 아직 읽히지 않습니다.

해치는 `HATCH` 엔티티로 DXF에 **내보내집니다**. 경계 루프는 패턴 이름(그룹 코드 2), 솔리드 채움 플래그(70), 그리고 해당 해치 자신의 각도와 축척(52/41)과 함께 나갑니다. 또한 가져오기 경로와 달리, 해석된 패턴 선 정의도 파일 안에 함께 기록됩니다(78과 53/43/44/45/46/79/49). 이 비대칭은 의도된 것입니다. KulmanLab은 이름을 자체 라이브러리에서 찾을 수 있지만, 파일을 받는 응용 프로그램에는 그 패턴이 없을 수 있으므로 선 자체가 함께 이동합니다.
