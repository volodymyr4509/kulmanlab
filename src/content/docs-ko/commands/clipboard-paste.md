# ClipboardPaste

`ClipboardPaste` 명령은 [ClipboardCopy](../clipboard-copy/)가 **시스템 클립보드**에 기록한 개체를 읽어 현재 도면에서 지정한 지점에 배치합니다. 실제 시스템 클립보드이므로 원본은 다른 도면일 수도, 다른 브라우저 탭일 수도, 그날 이른 시각의 작업 세션일 수도 있습니다.

## 붙여넣는 방법

1. `Ctrl+V`(macOS에서는 `Cmd+V`)를 누르거나 터미널에 `ClipboardPaste`를 입력합니다.
2. 브라우저가 클립보드 텍스트를 넘겨주는 동안 프롬프트에 **reading clipboard…**가 표시됩니다.
3. 읽기가 끝나면 프롬프트가 **pick insertion point**로 바뀌고, 붙여 넣을 형상의 미리보기가 커서를 따라옵니다.
4. **클릭**해서 개체를 배치합니다. 도면에 추가되고 선택된 상태로 남습니다.

미리보기는 복사 당시의 **참조점** — 원래 선택 영역 전체 경계의 왼쪽 아래 모서리 — 에 고정됩니다. 그 모서리가 커서 아래에 오므로 복사한 개체들의 상대 배치가 그대로 유지됩니다.

## 붙여넣을 때 일어나는 일

| 단계 | 동작 |
|------|------|
| **새 식별자** | 붙여 넣은 각 개체는 새 id를 받으므로 두 번 붙여 넣으면 서로 독립된 두 묶음이 됩니다 |
| **이동** | 개체는 커서 − 참조점 만큼 옮겨집니다 |
| **도면층 병합** | 대상 도면에 없는 참조된 도면층은 이름으로 추가됩니다 |
| **선종류 병합** | 대상 도면에 없는 참조된 선종류는 이름으로 추가됩니다 |
| **선택** | 이전 선택은 해제되고 붙여 넣은 개체가 선택됩니다 |

### 도면층과 선종류 병합

없는 테이블 항목은 추가되고 **있는 것은 건드리지 않습니다**. 클립보드가 빨간색 `WALLS` 도면층을 가져왔는데 대상 도면에 이미 파란색 `WALLS`가 있다면 대상의 정의가 이기고 붙여 넣은 개체가 거기에 합류합니다 — 파란색이 됩니다. 붙여넣기가 대상 도면의 무엇도 재정의하지 않습니다.

도면층 규칙이 다른 도면 사이를 오갈 때 이 점이 중요합니다. 도면을 건너 붙여 넣은 뒤 색이 예상과 다르면 [Layer Manager](../layer-manager/)를 확인하세요.

## 클립보드에 붙여넣을 것이 없을 때

ClipboardPaste는 ClipboardCopy가 만든 데이터만 받아들입니다. 클립보드에 있는 그 밖의 모든 것 — 일반 텍스트, 주소, 이미지, 다른 프로그램의 JSON — 은 거부되고 터미널이 이렇게 알립니다:

```
Clipboard has no copied entities
```

브라우저가 클립보드 접근을 아예 거부하면 메시지는 **Clipboard access denied**가 됩니다. 두 경우 모두 도면을 바꾸지 않고 명령을 끝냅니다.

## 키보드 참조

| 키 | 동작 |
|----|------|
| `Ctrl+V` / `Cmd+V` | ClipboardPaste 실행 |
| `Escape` | 취소 — 개체는 버려지고 아무것도 추가되지 않습니다 |

읽기 단계에서 취소해도 안전합니다. 이미 취소했거나 다른 명령을 시작한 뒤에 클립보드가 응답하더라도, 늦게 도착한 결과는 그때 활성인 작업을 방해하지 않고 버려집니다.

## 탭 사이의 복사

도면을 오가는 일반적인 흐름:

1. 원본 도면을 열고 형상을 선택한 뒤 `Ctrl+C`를 누릅니다.
2. 다른 탭으로 전환합니다 — 또는 앱의 두 번째 탭을 열고 다른 파일을 불러옵니다.
3. `Ctrl+V`를 누르고 삽입점을 클릭합니다.

두 탭은 출처가 같고 시스템 클립보드를 공유하므로 업로드되는 것이 없고 서버도 관여하지 않습니다. 데이터는 처음부터 끝까지 사용자 본인의 클립보드에 있는 JSON 텍스트입니다.

## 지원하는 개체

ClipboardCopy가 기록할 수 있는 모든 개체 유형을 ClipboardPaste가 다시 읽어들일 수 있습니다 — 자체 `.json` 형식과 같은 직렬화를 씁니다.
