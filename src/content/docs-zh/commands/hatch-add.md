# HatchAdd

`HatchAdd` 命令打开系统的文件选择框以上传 `.pat` 填充图案文件，无需先打开 [Hatch Manager](../hatch-manager/) 对话框。这与 Hatch Manager 中 **Add .pat File** 按钮触发的上传完全相同——HatchAdd 只是从终端直达那里的一条捷径。

## 上传图案文件

1. 在终端输入 `HatchAdd`，或点击 [Hatch Manager](../hatch-manager/) 对话框底部的 **Add .pat File**。
2. 在系统选择框中选择一个 `.pat` 文件。只接受标准的填充图案格式。

文件选择框一打开，命令即告结束——之后没有任何提示、点击或终端输入。文件一经选定，图案便完成注册并出现在 **User** 分组中。

## 上传时会发生什么

- **`.pat` 文件是一个容器，而不是单个图案。**一个文件通常定义许多具名图案，它们会被一并加入。这正是 HatchAdd 与 [FontAdd](../font-add/) 的分别所在，后者一个 `.ttf` 就是一种字体。
- **文件本身不会被保留。**它只被读取一次，拆分成各个图案，每个图案以自己的名称单独保存。因此你日后可以删掉其中一个图案而不惊动与它同来的其他图案——也因此 **User** 分组按名称的字母顺序排列，而不是按它们来自哪个文件。
- **名称与已有图案相同的图案会取代它。**这正是把权威定义覆盖到 KulmanLab 自身近似值之上的受支持做法：上传一份真正的 `acad.pat`，其中的 `ANSI31` 和其他标准名称的定义便会接管。
- **图案按用户保存，而不是按图纸保存。**它们存在浏览器中（IndexedDB），下次打开 KulmanLab CAD 时自动重新载入，并在每一张图纸中都可用。
- **不含有效图案定义的文件不会添加任何东西。**图案库保持原样。

## 键盘参考

HatchAdd 没有自己的键盘交互——整条命令就是浏览器原生的文件选择对话框。取消该对话框（或不选择文件）会让图案库保持不变。
