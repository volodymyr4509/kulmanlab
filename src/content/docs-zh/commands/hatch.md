# Hatch

`hatch` 命令用图案填充包围所点击点的区域。边界不是预先绘制的 —— 它由画布上已有的内容决定，因此四条端对端相接的独立[Line](../line/)围成一个区域，其效果与闭合的[Polyline](../polyline/)完全相同，而区域内的任何闭合图形都会变成填充不会触及的孤岛。

## 填充区域

1. 在终端输入 `hatch`，或点击工具栏上的 **Hatch** 按钮（图案样本图标）。
2. 在想要填充的区域内**点击一个点**。
3. 命令保持激活状态，因此可以继续点击以填充更多区域 —— 每次点击都会创建各自独立的 `Hatch` 图元。
4. 完成后按 **Enter**、**Space** 或 **Escape**。

```
  ┌─────────────┐        ┌─────────────┐
  │             │        │▓▓▓▓▓▓▓▓▓▓▓▓▓│
  │   ○         │  --->  │▓▓▓( )▓▓▓▓▓▓▓│   点击外边界内部；
  │             │        │▓▓▓▓▓▓▓▓▓▓▓▓▓│   圆保留为孤岛
  └─────────────┘        └─────────────┘
```

## 键盘参考

| 按键 | 操作 |
|-----|--------|
| `Enter` / `Space` | 完成 Hatch 命令 |
| `Escape` | 完成 Hatch 命令 (与 Enter/Space 相同) |

## 什么可以构成边界

以下图元类型的任意组合都可以构成边界，只要它们以任意组合方式端对端相连、没有任何缺口：

- [Line](../line/)
- [Arc](../arc/)
- [Circle](../circle/)（自身闭合的边界）
- [Ellipse](../ellipse/)（闭合的，或作为更大环路一部分的开放椭圆弧）
- [Polyline](../polyline/)（开放或闭合）和 [Rectangle](../rectangle/)
- [Spline CV / Spline Fit](../spline-cv/)——自身交叉的样条的每个环都是独立的区域

Text、Multileader 和 Dimension 图元永远不会被当作边界。

## 孤岛

在你选择的区域内完全闭合的任何东西 —— 一个圆、一条闭合多段线、另一个 hatch 的边界 —— 都会变成一个**孤岛**：填充在其边缘处停止，孤岛本身保持为空。将一个闭合图形放在另一个闭合图形内，填充会交替出现，每一层都遵循相同的内/外规则，形成填充中的孔中的填充。

## 点击失败时

如果你点击的点没有被包围，或者边界存在缺口，终端会解释原因，而不是悄无声息地什么都不做：

| 消息 | 含义 |
|------|------|
| "no boundary found" | 从点击点向任何方向都没有检测到任何东西 —— 附近根本没有边界 |
| "point is not enclosed" | 附近存在边界，但它形成的图形不包含你点击的点 |
| "boundary is open" | 最近的边界在某处有缺口 —— 追踪它并检查每个连接点是否精确 |
| "boundary too complex" | 边界环在遍历限制内无法闭合 —— 通常是重叠图元造成的混乱 |

点击失败后命令仍保持激活状态 —— 阅读消息、修正图形或在别处点击，然后重试。

## 选择图案

每个新的 hatch 都以 `ANSI31` 填充开始（或使用你*最后*编辑的 hatch 所用的任何图案）—— 绘制之前没有图案选择器。要使用不同的图案：

1. 选择一个已有的 hatch，在属性面板中打开其 **Pattern** 字段 —— 这会打开图案选择器，一个按每个图案来源分组的具名样本网格。
2. 点击一个图案以应用它 —— 填充会立即更新。

该选择也会成为你用 `hatch` 命令创建的*下一个* hatch 的默认值，就像选择图层或颜色会延续下去一样。因此，要用某个特定图案对多个新区域进行 hatch：先填充一个区域，设置一次它的图案，然后继续 hatch —— 之后的每次填充都已经应用了该图案开始。

请参阅 [Hatch Manager](../hatch-manager/) 以上传你自己的 `.pat` 图案文件并浏览完整的图案库。

**SOLID** 只是图案列表中的一个普通条目，不是单独的复选框或模式 —— 选择它的方式与选择 ANSI31 或任何其他具名图案完全相同。

## 属性

| 属性 | 含义 |
|------|------|
| Pattern | 图案名称，来自共享的图案词汇表（参阅 [Hatch Manager](../hatch-manager/)） |
| Pattern Scale | 缩放图案线条的间距 —— 值越大，图案线条之间的距离越远 |
| Pattern Angle | 独立于边界旋转图案 |
| Origin X / Origin Y | 图案自身重复的锚定位置，以图形坐标表示 |

移动、旋转、镜像或缩放 hatch 会一并带走其图案的位置，因此填充始终与边界保持对齐 —— 变换后无需重新设置缩放或角度。

## 边界的夹点编辑

选中的 hatch 抓取其边界的方式与 Polyline 抓取其顶点的方式相同 —— 在每个两条边相接的角上有一个夹点，在每条边的中点也有一个（像圆形或椭圆形 hatch 这样的闭合环则改为在其四个轴点上抓取）。

| 夹点 | 作用 |
|------|------|
| **角点** | 移动该角点。直边会精确跟随；圆弧会重新拟合以继续经过两侧相邻的边；椭圆或样条边只能落在其自身曲线上的某处，因此角点会吸附到该曲线上最近的点 |
| **边中点 —— 直线、椭圆或样条边** | 滑动整条边；两侧的边会被裁剪或延伸以保持与其相连 |
| **边中点 —— 圆弧边** | 通过光标使圆弧**弯曲**，而不是滑动它 —— 两端都精确保持在原位，边界中其他部分都不会移动 |
| **中心**（整个 hatch） | 为整个 hatch 激活 [Move](../move/) |

拖动预览会将边界显示为虚线轮廓，而不是实心填充 —— 原来的填充会一直在下方保持可见，直到你松开鼠标，因为预览只能画在已有内容之上，永远无法从中移除任何东西。

## DXF — HATCH 图元

Hatch 从 `HATCH` 图元**导入**：KulmanLab 读取边界几何图形，以及图案的名称、比例和角度（DXF 组码 70/41/52）—— 它**不会**读取 内联写入文件中的图案自身线条定义。相反，图案名称会在 KulmanLab 自己的图案库中查找（内置默认图案加上你在 [Hatch Manager](../hatch-manager/) 中上传的任何内容）。库中不存在的名称会回退为 ANSI31，使图形仍然显示为已 hatch，并且会记录一次提示。

由其他应用程序写入的样条线约束环路（DXF 边界边类型 4）尚不支持读取。

填充以 `HATCH` 实体**导出**到 DXF。边界环随图案名称（组码 2）、实体填充标志（70）以及该填充自身的角度和比例（52/41）一同写出——并且与导入路径不同，图案已解析的线定义也会内联写入（78，配合 53/43/44/45/46/79/49）。这种不对称是刻意的：KulmanLab 可以在自己的库中解析名称，但接收文件的应用程序未必有那个图案，因此线条会随文件一起走。
